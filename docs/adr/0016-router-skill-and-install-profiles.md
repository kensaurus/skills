# 0016. One command to remember, and install profiles inside the one package

Status: Accepted            Date: 2026-11-17

## Context

Users reported the pack was hard to use because they had to memorize skill and
command names. Research on 2026-11-17 found:

- The two most-installed packs solve this inside the agent, not in docs:
  mattpocock/skills ships an `ask-matt` router skill, and obra/superpowers
  injects a bootstrap skill with a SessionStart hook. No leading pack has a
  web "what should I say" finder.
- Library size costs accuracy. Song & Wei, "More Skills, Worse Agents?"
  (2026-05-15, https://openreview.net/forum?id=RQuOPsCKnc), measured pass
  rates falling up to 21% at a 202-skill library, caused by wrong skill
  selection, with context overhead near zero. Dong et al. (2026-08-12,
  https://arxiv.org/abs/2608.11888) found seemingly relevant skills cause more
  failures than irrelevant ones.
- Hosts truncate long listings: Claude Code at 1% of context (names only over
  budget), Codex CLI at 2%, Cursor and Zed with caps of their own.
- Leading packs are small (15 to 56 skills) or split into opt-in bundles.

Measured here: the full listing is 38,994 characters at a 39,000 ratchet; the
`core` profile's listing is about 6,500.

## Decision

1. **A router skill, `kenji`.** `/kenji <the job>` names the one playbook that
   fits, says what the user gets, and runs it; it asks at most one question.
   It is `disable-model-invocation: true`, so it adds nothing to the listing.
   Its full skill index is generated by `scripts/generate-skill-index.mjs`.
2. **Install profiles, in one package.** `profiles.json` defines `core` (28
   skills, part of every profile), `web`, `backend`, `mobile`, `growth`, and
   `maintain`. `--profile <csv>` installs the union; `all` stays the default;
   `--prune` removes only this pack's skills outside the profile.
   `validate-skills` fails when a skill is in no profile.
3. **Auto-routing is unchanged.** Every skill a user installs keeps its
   description in the listing (ADR-0008 stands). Profiles reduce the listing
   by installing less, at the user's choice.
4. **Trigger evals gate description changes.** `evals/` holds one case per
   core route for `claude plugin eval`. They spend real tokens, so they are a
   maintainer step and not part of `npm test`.

## Consequences

- The npm package is still one package (ADR-0005). Profiles are a filter in
  the installer, not separate packages or plugins.
- Docs lead with `/kenji` and a three-step quick start; trigger tables remain
  as reference.
- A new skill must be added to a profile or `npm test` fails.

## Rejected

- **Making most skills `/`-only** (a small auto-routed core). It is the
  strongest fix the research supports, but it reverses ADR-0008 with no local
  measurement. Revisit with the trigger evals' with-and-without numbers.
- **A SessionStart bootstrap hook** like superpowers. It adds tokens to every
  session for every user, and the pack's hooks are opt-in by design.
- **An auto-invocable router.** Its description would exceed the listing
  ratchet (ADR-0010), and the model already routes from the listing; the
  router's value is the one name a person types.
- **Splitting the Claude plugin into per-profile plugins now.** Whether a
  marketplace entry may list individual skill folders was not confirmed.
- **Rewriting all 162 descriptions to front-load triggers.** Without eval
  results, a mass rewrite risks the mis-selection it is meant to fix.
