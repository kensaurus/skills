# Knip config recipes and the ratchet job

Starting points, not drop-ins. Author the config from the detected stack
(Phase 0), then let configuration hints correct you. Every pattern below
exists to replace an `ignore` someone would otherwise reach for.

## Contents

- Vite + React + Supabase
- Next.js App Router
- Monorepo (pnpm / turbo / nx)
- Tags beat config
- Companion tools
- The ratchet job
- Hint symptom → correct fix

Install locally, never globally:

```bash
npm i -D knip        # pnpm add -D knip · yarn add -D knip · bun add -d knip
```

Knip already respects `.gitignore`. Do not re-list `node_modules`, `dist`,
`build`, or `.next`. Do not re-declare entry points that an auto-detected
plugin already adds — a redundant pattern is drift waiting to happen.

## Vite + React + Supabase

The four things that make this stack look 90% dead on a first run:
glob-loaded routes, a generated types file, a design-system barrel, and
`supabase/functions/**` (Deno — never in the Vite module graph).

```json
{
  "$schema": "https://unpkg.com/knip@6/schema.json",
  "workspaces": {
    ".": {
      "entry": [
        "src/main.tsx!",
        "src/routes/**/*.{ts,tsx}!",
        "vite.config.ts",
        "tailwind.config.ts"
      ],
      "project": ["src/**/*.{ts,tsx}!"],
      "ignoreIssues": { "src/types/supabase.ts": ["exports", "types"] },
      "ignoreDependencies": ["tailwindcss", "autoprefixer"],
      "ignoreExportsUsedInFile": { "interface": true, "type": true }
    },
    "supabase/functions/*": {
      "entry": ["index.ts!"],
      "project": ["**/*.ts!"]
    }
  }
}
```

Why each line:

| Line | Replaces | Reason |
|---|---|---|
| `src/routes/**` in `entry` | ignoring `src/routes` | Loaded by `import.meta.glob`; nothing imports them, so they are entry points by definition |
| `!` suffix | — | Marks the pattern as production, so `--production` keeps it |
| `vite.config.ts`, `tailwind.config.ts` as entry | ignoring the configs | Config files are entry points; they also pull deps that look unused |
| `ignoreIssues` on `src/types/supabase.ts` | `ignore` on the file | Generated by `supabase gen types` — regenerate, never hand-edit. Scoped to the two issue types it actually over-reports, so a genuine unresolved import in that file still surfaces; a blanket `ignore` would silence those too |
| `ignoreExportsUsedInFile` | `--exclude types` | Kills the unused-`interface`/`type` flood without hiding real unused types |
| `ignoreDependencies` | blanket `ignore` | Referenced only from PostCSS/Tailwind config strings |
| separate `supabase/functions/*` workspace | ignoring the folder | Deno runtime with its own graph; as part of the app workspace every function reports unused |

Add `paths` (tsconfig semantics) if `@/*` aliases come back unresolved:

```json
{ "paths": { "@/*": ["src/*"] } }
```

## Next.js App Router

The Next plugin already knows `app/**/page.tsx`, `layout.tsx`, `route.ts`,
`middleware.ts`. Do not re-list them.

```json
{
  "$schema": "https://unpkg.com/knip@6/schema.json",
  "next": { "entry": ["instrumentation.ts!", "app/**/opengraph-image.tsx!"] },
  "ignoreExportsUsedInFile": { "interface": true, "type": true },
  "ignoreDependencies": ["sharp"]
}
```

Server Actions exported from `"use server"` modules are reached through the
framework, not an import. If they surface as unused, tag the deliberate
ones `@public` rather than ignoring the file — a tag is local and Knip
reports a **tag hint** when it stops being needed.

## Monorepo (pnpm / turbo / nx)

A monorepo configured as one root project reports the whole repo as dead.
Declare workspaces explicitly.

```json
{
  "$schema": "https://unpkg.com/knip@6/schema.json",
  "workspaces": {
    "apps/*": { "entry": ["src/main.tsx!"], "project": ["src/**!"] },
    "packages/*": { "entry": ["src/index.ts!"], "project": ["src/**!"] },
    "packages/config": { "entry": ["*.js"] }
  }
}
```

- `--workspace <name>` scopes a run to one package plus its ancestor,
  dependency, and dependent workspaces. Narrowing it is also a way to hide
  findings — treat a scope change like a baseline change.
- `--strict` isolates workspaces and considers only direct dependencies —
  it catches a package importing something it never declared.
- A `packages/*` public API is genuinely exported for consumers: tag it
  `@public` instead of adding entry patterns for every symbol.

## Tags beat config

Config exemptions rot silently. Tags sit next to the code, and Knip emits
a tag hint when one is no longer necessary.

```ts
/** @public */
export const publicApiFn = () => {};   // deliberate API — not reported

/** @internal */
export const forTestsOnly = () => {};  // not reported in --production

export const Component = () => {};
/** @alias */
export default Component;              // suppresses the duplicate-export finding
```

Custom tags with CLI/config control:

```bash
npx knip --tags=-lintignore,-internal   # '-' excludes, '+' includes only
```

`@beta` behaves like `@public`. `@alpha` and `@experimental` are ignored.

## Companion tools

Knip owns the module graph and nothing else. Officially recommended
companions:

| Class | Tool | Note |
|---|---|---|
| Unused vars/imports *inside* files | ESLint, Biome, or oxlint | Knip explicitly does not do this |
| Bulk removal of unused code in files | `remove-unused-vars` | Consumes linter output; run it, then re-run Knip |
| Circular dependencies | dpdm, madge, skott | Pack owner is `enhance-arch-boundaries` |
| Copy-paste duplication | jscpd | `--min-tokens 50` default; raise to cut boilerplate noise |
| Compiler-level unused locals | `tsc --noEmit` | Needs `noUnusedLocals` + `noUnusedParameters` on |

## The ratchet job

`--max-issues` defaults to `0`. Set it to the post-cleanup count and only
ever lower it. Run both modes; production mode is the number that should
reach zero first.

```json
{
  "scripts": {
    "knip": "knip --production --max-issues 0",
    "knip:all": "knip --max-issues 3 --treat-config-hints-as-errors"
  }
}
```

```yaml
  dead-code:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 24
          cache: npm
      - run: npm ci --ignore-scripts
      - name: Dead code (production)
        run: npm run knip
      - name: Dead code (all)
        run: npm run knip:all
```

CI calls the **scripts**, not raw flags, so local and CI cannot drift.

Then add `dead-code` to the aggregator's `needs:` list rather than making
it a second required check — see `housekeep-gates`.

Exit codes: `0` clean · `1` issues found · `2` Knip failed to run. Treat
`2` as a broken gate, never as a pass; a job that only checks for `1` will
go green on a crashed run.

`--treat-config-hints-as-errors` is what stops the config from silently
decaying after the plan pass — without it, a stale `entry` pattern degrades
the signal and nobody notices. **It belongs on the default-mode run only:**
Knip computes `isDisableConfigHints = --no-config-hints || isProduction`,
so under `--production` hints are never collected and the flag is inert.

Two flags deliberately omitted: `--cache` writes to
`node_modules/.cache/knip`, which `npm ci` wipes on every run (add an
`actions/cache` step if you want it), and `--no-progress` is redundant
because Knip already disables progress in CI.

**Guard the ratchet, not just the number.** `--max-issues` totals only
issue types whose rule is `error`, so a `rules: { files: "warn" }` entry
reports every dead file and still exits `0`. Same class of bypass:
`--no-exit-code`, `--exclude`, a narrowed `--include`, `--workspace`
scoping, and the `ignore*` family. Review changes to `knip.json` and the
job's flags as carefully as the count itself.

## Hint symptom → correct fix

| Symptom | Correct fix | Not this |
|---|---|---|
| Whole directory unused | Add `entry` pattern for its real entry | `ignore` the directory |
| `vite.config.ts` reported unused | Enable/disable that plugin explicitly | `ignore` the file |
| Flood of unused `interface`/`type` | `ignoreExportsUsedInFile: { interface: true, type: true }` | `--exclude types` |
| Unresolved path-alias imports | Add `paths` (tsconfig semantics) | `ignore` the importer |
| Node builtins as unused deps | `ignoreDependencies` | blanket `ignore` |
| Test files reported | `--production` | negated `project` patterns |
| Generated file's exports unused | `ignore` that one file *(legitimate)* | — |
